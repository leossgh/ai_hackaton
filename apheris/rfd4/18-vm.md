# Run on your hackathon VM

Your VM has every Foundry model as a Docker image, already downloaded, and one H100 GPU.
You run them with `docker run`. There is no Foundry Hub here, so skip the
`apheris-foundry` commands in the other pages and use the commands below. Every setting those
pages describe exists here as a flag.

## Set up once

```bash
aws s3 sync s3://apheris-oslo-hackathon/rfd4-proteina/docs/ ~/rfd4
cd ~/rfd4
```

Run every command below from `~/rfd4`, the folder that holds `Data/` and `Settings/`.

`foundry-toolkit module list` lists the images. To see every option of one, run
`foundry-toolkit module describe --name apheris-rfd4-proteina --version 0.3.0-her2-novel-2026-11-09`.

## Run a design

These options go in front of every command:

```bash
RUN="docker run --rm --gpus all --shm-size 16g --user $(id -u):$(id -g) -e HOME=/tmp -v /etc/passwd:/etc/passwd:ro -v $PWD:/work -w /work"
```

`-v $PWD:/work` lets the container read and write your current folder. `--user` and the `/etc/passwd` mount make the files yours; some folding models fail without the mount.

Redesign trastuzumab's CDRH3 against HER2, 100 designs (about 30 s each):

```bash
$RUN $Q:apheris-rfd4-proteina-v0.3.0-her2-novel-2026-11-09 module-run design \
  --input Data/12-her2/her2_cdrh3.yaml --output runs/her2/design \
  --num-replicates 100 --seed 1 --recycle-strategy high/front_loaded
```

Designs land in `runs/her2/design/generation/inference_samples/*/*_generated.cif`, with
per-design metrics in `runs/her2/design/generation/inference_metrics/per_example_metrics.csv`.

Other inputs work the same way: `Data/03-vhh/pmvk_caplacizumab.cif.zst` (VHH) or
`Data/03-fv/design.json` (paired VH/VL) with the antibody image, and the other `Data/` folders
with the general model. Write your own spec as in [How to design an antibody](15-antibody-design.md).

### Design flags

The `Settings/*.json` files use the Hub's names. On the VM, write them as flags:

| Settings name | Flag | What it does |
| --- | --- | --- |
| `numReplicates` | `--num-replicates 100` | Designs per input, up to 200 |
| `batchSize` | `--batch-size 1` | Inputs per batch |
| `seed` | `--seed 1` | Random seed |
| `recycleStrategy` | `--recycle-strategy high/front_loaded` | Compute per design. Use `high/front_loaded` for antibodies |
| `sequenceTsrK` | `--sequence-tsr-k 2` | Sequence randomness: 1 most varied, 4 default |
| `resampleHotspots` | `--resample-hotspots true` | Pick 2-3 target atoms near your hotspots for each design |
| `partialTrajectoryFraction` | `--partial-trajectory-fraction 0.4` | Refine an earlier design (see below) |
| `inverseFolding` | `--inverse-folding true` | Keep a backbone, design new sequences |
| `compile` | `--compile true` | Faster from about 8 designs per length |
| `refold`, `refoldTopN` | `refold-prepare --top-n 20` | A separate step here, see below |

### Refine a design

Partial diffusion re-runs part of the trajectory on one design, so you get close variants:

```bash
D=runs/her2/design/generation/inference_samples/her2_cdrh3_0/her2_cdrh3_0_generated.cif
$RUN $Q:apheris-rfd4-proteina-v0.3.0-her2-novel-2026-11-09 module-run design \
  --input $D --output runs/refine --partial-trajectory-fraction 0.4 --num-replicates 8 --seed 2
```

Inverse folding keeps that design's backbone and writes new sequences for it: replace
`--partial-trajectory-fraction 0.4` with `--inverse-folding true`.

### General model

The general model's weights sit in an older image. Copy them out once:

```bash
cid=$(docker create $Q@sha256:59409a17762fcc180113c30cd00e68d397e1af4ff145080775779119f3d548a2)
docker cp $cid:/weights ~/weights-release && docker rm $cid
```

Then run any design image with them, adding `-v ~/weights-release:/release:ro` and `--data-path /release`:

```bash
$RUN -v ~/weights-release:/release:ro $Q:apheris-rfd4-proteina-v0.3.0-antibody-2026-10-30 \
  module-run design --input Data/02-miniprotein/design.yaml --output runs/mini \
  --data-path /release --num-replicates 4 --seed 42
```

## Check designs by refolding

Refolding asks a folding model whether it agrees with the design. Three steps:

1. Pick the best designs and write the folding inputs:

   ```bash
   $RUN $Q:apheris-rfd4-proteina-v0.3.0-her2-novel-2026-11-09 module-run refold-prepare \
     --input runs/her2/design --output runs/her2/prepared --top-n 20
   ```

2. Fold them. Pick an image from the table; each starts with its own command, which `docker inspect` reads:

   ```bash
   IMG=$Q:apheris-boltz-v1.3.0-boltz2
   CMD=$(docker inspect -f '{{join .Config.Cmd " "}}' $IMG)
   $RUN $IMG $CMD predict \
     --input runs/her2/prepared/holo/queries.json --output runs/her2/boltz2 \
     --template-paths runs/her2/prepared/holo/template.cif --write-detailed-scores true \
     --num-diffusion-samples 1 --seeds 42 --query-failures skip
   ```

   For a model without a template, leave out `--template-paths`. Use a separate `--output`
   folder per model.

3. Score them:

   ```bash
   $RUN $Q:apheris-rfd4-proteina-v0.3.0-her2-novel-2026-11-09 module-run refold-score \
     --input runs/her2/design --output runs/her2/scored-boltz2 \
     --predictions runs/her2/boltz2 --model boltz2
   ```

   Results are in `runs/her2/scored-boltz2/refold_metrics.csv`, one row per design.

**For the HER2 example, `pass` stays empty.** The example keeps HER2 and the antibody framework in
place relative to each other, not in absolute coordinates, so the scorer cannot measure how far
the antibody moved and says so in `pass_note`. Rank on `min_ipae` (lower is better), `iptm` and
`binder_plddt` instead, and compare scores only within one folding model.

[`Scripts/run-her2.sh`](Scripts/run-her2.sh) runs all three steps on the HER2 example:
`bash Scripts/run-her2.sh all` (4 designs, about 4 minutes).

## Other tasks

- **Metrics**: `module-run metrics --input runs/her2/design/generation --output runs/metrics` recomputes design metrics. Clustering (`--cluster`) is not available: the images have no Foldseek.
- **Fine-tuning**: `module-run finetune --task-mix antibody` trains on your own structures; see [Advanced routes](07-advanced.md) for the data format. Pass the result to `design` with `--checkpoint`.

## Before you submit

Filter every design with `abguard` before you rank it. Most HER2 designs from the
conservative and balanced settings are already in the screen and fail the novelty rule.
