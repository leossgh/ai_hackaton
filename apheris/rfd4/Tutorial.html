Create a protein, design a binder or refine a candidate. Example inputs and settings are included.

Run on your hackathon VM

Run a design

These options go in front of every command:

RUN="docker run --rm --gpus all --shm-size 16g --user $(id -u):$(id -g) -e HOME=/tmp -v /etc/passwd:/etc/passwd:ro -v $PWD:/work -w /work"

-v $PWD:/work lets the container read and write your current folder. --user and the /etc/passwd mount make the files yours; some folding models fail without the mount.

Redesign trastuzumab's CDRH3 against HER2, 100 designs (about 30 s each):

$RUN $Q:apheris-rfd4-proteina-v0.3.0-her2-novel-2026-11-09 module-run design \
  --input Data/12-her2/her2_cdrh3.yaml --output runs/her2/design \
  --num-replicates 100 --seed 1 --recycle-strategy high/front_loaded

Designs land in runs/her2/design/generation/inference_samples/*/*_generated.cif, with per-design metrics in runs/her2/design/generation/inference_metrics/per_example_metrics.csv.

Other inputs work the same way: Data/03-vhh/pmvk_caplacizumab.cif.zst (VHH) or Data/03-fv/design.json (paired VH/VL) with the antibody image, and the other Data/ folders with the general model. Write your own spec as in How to design an antibody.

Refine a design

Partial diffusion re-runs part of the trajectory on one design, so you get close variants:

D=runs/her2/design/generation/inference_samples/her2_cdrh3_0/her2_cdrh3_0_generated.cif
$RUN $Q:apheris-rfd4-proteina-v0.3.0-her2-novel-2026-11-09 module-run design \
  --input $D --output runs/refine --partial-trajectory-fraction 0.4 --num-replicates 8 --seed 2

Inverse folding keeps that design's backbone and writes new sequences for it: replace --partial-trajectory-fraction 0.4 with --inverse-folding true.

Check designs by refolding

Refolding asks a folding model whether it agrees with the design. Three steps:

  1. Pick the best designs and write the folding inputs:
    $RUN $Q:apheris-rfd4-proteina-v0.3.0-her2-novel-2026-11-09 module-run refold-prepare \
  --input runs/her2/design --output runs/her2/prepared --top-n 20
  2. Fold them. Pick an image from the table; each starts with its own command, which docker inspect reads:
    IMG=$Q:apheris-boltz-v1.3.0-boltz2
CMD=$(docker inspect -f '{{join .Config.Cmd " "}}' $IMG)
$RUN $IMG $CMD predict \
  --input runs/her2/prepared/holo/queries.json --output runs/her2/boltz2 \
  --template-paths runs/her2/prepared/holo/template.cif --write-detailed-scores true \
  --num-diffusion-samples 1 --seeds 42 --query-failures skip

    For a model without a template, leave out --template-paths. Use a separate --output folder per model.

  3. Score them:
    $RUN $Q:apheris-rfd4-proteina-v0.3.0-her2-novel-2026-11-09 module-run refold-score \
  --input runs/her2/design --output runs/her2/scored-boltz2 \
  --predictions runs/her2/boltz2 --model boltz2

    Results are in runs/her2/scored-boltz2/refold_metrics.csv, one row per design.

For the HER2 example, pass stays empty. The example keeps HER2 and the antibody framework in place relative to each other, not in absolute coordinates, so the scorer cannot measure how far the antibody moved and says so in pass_note. Rank on min_ipae (lower is better), iptm and binder_plddt instead, and compare scores only within one folding model.

Scripts/run-her2.sh runs all three steps on the HER2 example: bash Scripts/run-her2.sh all (4 designs, about 4 minutes).

Other tasks

  • Metrics: module-run metrics --input runs/her2/design/generation --output runs/metrics recomputes design metrics. Clustering (--cluster) is not available: the images have no Foldseek.
  • Fine-tuning: module-run finetune --task-mix antibody trains on your own structures; see Advanced routes for the data format. Pass the result to design with --checkpoint.

Before you run

RFD4-Proteina generates protein sequences and all-atom structures together. Start with a new protein, a binder or refinement.

Set up once

Get your Foundry URL and access to Design Proteins, Predict Structure and Score Refolded Designs from your platform team. Check the available weight builds. Foundry setup is an optional online reference.

The workflow IDs are rfd4-proteina-design, predict and rfd4-proteina-refold-score, respectively.

For an agent or command-line session, start with connection and submission instructions.

  1. Download the chosen input ZIP from this guide and extract it. Upload its Data/<example>/ folder, keeping the spec and structures together.
  2. Apply the values in its linked Settings/ file to the workflow parameters. Keep settings outside the upload. Your client supplies input, output and weight selection.
  3. Run Design Proteins. Antibody pilots request one candidate. Other fresh-design examples request four. Both use batch size 1 and seed 42. Counts are per input.
  4. Open design/result.json for structures, metrics and logs, then evaluate the candidates.

Put each setting in the right place: design length, fixed atoms and hotspots belong in design.yaml / design.json or the annotated CIF. Generation settings such as numReplicates belong to Design Proteins. Folding settings such as seeds belong inside Predict Structure's modelParams. The technical reference lists accepted fields and defaults. Design results live in <output>/design/. Manifest paths are relative to that task directory. Refolding preparation writes <output>/refold/.

Design requests one NVIDIA GPU, eight CPUs and 64 GiB host RAM. GPU memory depends on the input. These examples use CIF, not PDB.

Also available: motifs, enzymes, ligands and DNA, training and metrics, and troubleshooting.

  3. Submit the job, check its final state and download the complete outputs.

Goal: generate a new 100-residue sequence and fold, without a target.

Upload Data/01-monomer/, select the general release weights and use Settings/01-monomer.json. The annotated CIF encodes the length. Its spec preserves those instructions:

monomer:
  input: monomer-short.cif.zst

2. Design a binder

Supply a target and binding patch. Choose the binder format:

The miniprotein example creates a 50–80 residue binder. Antibody examples keep framework sequence and internal geometry, generating three CDRs for VHH or six for Fv. Select antibody-2026-10-30 weights for the antibody exercises. A complete Fab also includes constant domains. This exercise designs its Fv region.

For a hackathon, complete one supplied antibody example through design, prediction and scoring before increasing the count or changing the antigen. For a new antigen, provide its prepared CIF, the intended binding patch, framework choice and CDR length ranges. Inspect the structure's chain and residue map before editing conditions. Keep the original sample as a reference.

Run the selected example using the shared steps. Inspect the generated complex: does the binder reach the intended patch without clashes? The CSV's designed_sequences identifies the binder chains, including retained framework sequence. Keep both domains for Fv.

For your own target: replace the structure and update chain IDs, residue ranges and hotspot atoms in the spec. Keep antigen sequence fixed (C_SEQ) and its backbone in absolute coordinates (C_CRD) for pose scoring. Selections use original mmCIF label_seq_id.

The miniprotein spec keeps target chain A and inserts a new protein chain:

pdl1_miniprotein:
  input: target.cif.zst
  contig: "50-80, /0, A17-131"
  conditions:
    C_CRD: {true: [{select: "sel('A/*/*/[N,CA,C,O]')"}]}
    C_SEQ: {true: [{select: "sel('A')"}]}
    C_HOT:
      true:
        - select: "sel('A/*/56/[CG,OH]')"
        - select: "sel('A/*/115/[CG,SD]')"
        - select: "sel('A/*/123/[CD2,OH]')"

50-80 is the generated length range. /0 starts the target chain. The conditions preserve target backbone and sequence and request contacts to the listed atoms. Audit every selection when replacing the target.

For trastuzumab and HER2, start from the fine-tuned HER2 models.

Next: evaluate, or read the antibody-specific notes.

Antibody notes
  • Keep the scaffold: retain framework sequence, disulfide cysteines and internal backbone geometry (C_CRDGRP: 1). Use a shared group for paired VH/VL frameworks and C_CATH: "2.60.40" on antibody chains. Leave intended CDRs free. Derive boundaries from the actual structure.
  • Use the supplied schedule: antibody settings use high/front_loaded. Keep hotspot resampling off when a specific contact is essential.
  • Inspect antigen contacts: Fv scoring chooses one chain of interest. The other antibody domain counts as a partner, so a low interface PAE can reflect VH–VL confidence. The apo query also contains only the chosen chain.
  • Split incompatible refolding batches: if variable light-chain CDR lengths break the shared-template check, prepare one candidate at a time with the CPU refold-prepare task and top_n: 1. The pilot already generates and prepares one candidate. Keep existing designs when preparing larger runs.

See the input reference for custom specs, or inspect the supplied Fv specification. When changing antigen, verify that every framework, target and hotspot selection still names the intended atoms. Inspect antigen–CDR contacts and clashes in the generated and refolded complexes before accepting a candidate.

Exercise 3

3. Refine a binder

Goal: explore nearby versions of a promising design. Partial diffusion changes both sequence and structure. Evaluate children to establish improvement.

  1. Upload one RFD4-Proteina *_generated.cif from an earlier run. Preserve its annotations and use the generated complex, rather than a predictor's refold.
  2. Keep the parent's checkpoint family and recycle schedule. Use miniprotein settings or antibody settings: eight children, partialTrajectoryFraction: 0.4, hotspot resampling off.
  3. Refold and compare children with the parent using the same prediction settings. Record each child's parent and fraction.

The fraction re-runs 40% of the 60 sampling steps. Smaller fractions generally stay closer to the parent. Larger ones explore further. It does not specify a structural displacement. An experimental binder first needs an explicit annotated redesign problem.

Inspect parents before multiplying them: Adaptyv refinement also propagated an unwanted terminal tail.

Exercise 4

4. Redesign trastuzumab for HER2

Two fine-tuned weights redesign the CDRH3 loop of trastuzumab, an antibody that binds the HER2 receptor. Together with one sampling setting they give four models. They learned from a public lab screen of trastuzumab variants, so their loops match measured HER2 binders far more often than the general antibody model's do. Use them as a starting point, then filter and rank the designs yourself.

Terms

Term Meaning
CDRH3 The third loop of the antibody heavy chain that touches the target. It makes most of trastuzumab's contact with HER2. In the example file it is heavy chain B, residues 99 to 108 in the file's own numbering, sequence WGGDGFYAMD in trastuzumab.
FACS screen The lab experiment the models learned from. Chinery et al. made about 524,000 trastuzumab variants, each with a different CDRH3, and sorted them by how well they bind HER2 into high, medium and low binders.
Known binder A design whose CDRH3 the screen labelled high.
Known non-binder A design whose CDRH3 the screen labelled low.
SPR binder A CDRH3 whose binding strength (affinity) was measured by surface plasmon resonance. The challenge data lists them.
Challenge filter The optimisation track's novelty rule. A design passes if its CDRH3 differs at 2 or more of its 10 positions from every sequence in the provided data (every screened variant and every SPR design) and is at most 70% identical to trastuzumab's CDRH3 (at least 3 of 10 positions changed).
Weight A named set of trained model parameters on Foundry. You choose one with --weight.
sequenceTsrK A decimal number above 0 that sets how random the sequence of each design is. The default is 4. Higher values make the model pick the sequences it rates most likely, so designs repeat more. 1 removes that sharpening and gives the most varied sequences. Values below 1 are allowed but we have not tested them. It does not change how the 3D structure is sampled.
Seed A number that fixes the random choices of a run, so the same seed gives the same designs.
Interface error Protenix's lowest predicted aligned error between antibody and HER2 residues after refolding a design, in ångström. Lower means Protenix is more confident the design fits HER2.

What we did

  1. Started from NVIDIA's antibody model (weight antibody-2026-10-30), which designs CDR loops on a fixed antibody framework.
  2. Picked training examples from the screen. We chose a varied set of high binders.
  3. Placed each loop on a real structure. Every chosen loop was put onto the crystal structure of trastuzumab bound to HER2 (PDB 1N8Z).
  4. Taught the model to redesign only CDRH3. The rest of the antibody and HER2 stay fixed. This gave the weight her2-2026-11-07.
  5. Trained a second weight on pairs. Starting again from the antibody model, we showed it pairs of one high and one low binder and rewarded it for preferring the high one. This gave the weight her2-novel-2026-11-09.
  6. Checked every model. Each made 300 designs (seeds 1, 2 and 3, 100 designs each), except HER2 novel, which made 100 (seed 1). We compared every design with the screen and refolded it with Protenix.

Run a model

  1. Set up the CLI and log in as in CLI setup. Run every command below from the extracted tutorial folder, the one that holds Data/ and Settings/.
  2. Check that your deployment lists the HER2 weights: apheris-foundry workflows models --workflow rfd4-proteina-design.
  3. Submit the HER2 example. This runs HER2 balanced with the HER2 settings:
apheris-foundry workflows run --workflow rfd4-proteina-design \
  --input Data/12-her2 --weight her2-2026-11-07 \
  --param sequenceTsrK=2 --param numReplicates=100 --param batchSize=1 \
  --param seed=1 --param recycleStrategy=high/front_loaded \
  --param refold=true --param refoldTopN=20 --wait
  1. Download the results, replacing the job ID with the one the run printed:
apheris-foundry jobs download --id "<design-job-id>" --output runs/her2
  1. Evaluate the designs.

For another model, change --weight and sequenceTsrK as in the models table. For HER2 conservative or HER2 novel, remove --param sequenceTsrK=2. The other parameters are explained in Parameters.

Keep in mind

  • The screen measured binding, not affinity. These models propose likely binders. Nothing trained them to improve affinity, so use the SPR data for that.
  • Only CDRH3 changes. To change other CDRs as well, redesign them with the antibody model.
  • Filter before you rank. Most conservative and balanced loops are already in the screen and fail the challenge filter. Apply the filter to every design first.
  • HER2 novel was tested on one seed. Its numbers come from 100 designs.
  • Do not rank on CDRH3 refold agreement. Protenix does not reproduce trastuzumab's own CDRH3 loop, so a mismatch there says little.

Evaluate candidates

Generation proposes candidates. Refolding checks whether another predictor recovers their folds and poses. Experiments establish binding and specificity.

1. Prepare

The pilot settings enable refold and prepare every candidate. Keep design/, refold/holo/ and refold/selection.csv. A failed preparation can leave valid designs. Read refold/error.json and split incompatible batches.

2. Predict

Upload refold/holo/ to Predict Structure. Select a model and weight offered by your deployment. The cofolding modules support these choices:

OpenFold3 of3ob / of3p2 openfold3-of3ob / openfold3-of3p2 Yes
Protenix v2 / v1-default protenix-v2 / protenix-v1 Yes
Boltz-2 boltz2 boltz2 Yes
Mol-1 base mol1-base Yes
Boltz-1 boltz1 boltz1 No
ESMFold2 release esmfold2-release No

Models without a template fold the target unguided. Run them with the untemplated settings below, even for binders.

Mol-1 uses the shared prediction workflow. For Boltz, select --model boltz --weight boltz2 explicitly. The optional weights field is a checkpoint-path override. Select build names such as boltz2 through the client. Put the holo model settings inside modelParams:

{"template_paths": ["template.cif"], "write_detailed_scores": true,
 "num_diffusion_samples": 1, "seeds": [42], "query_failures": "skip"}

Clients may serialize this object as JSON for modelParams. Preserve its keys and value types. In the Hub CLI, use --model-params @file.json, not --param modelParams=.... Keep model and weight selection outside that object.

Templates contain conditioned antigen/framework residues, not generated CDRs. Monomers have no template: use untemplated settings. No MSA upload is needed. Optional apo prediction uses those same untemplated settings and the same model/weights. It does not change automated pass/fail. Use the template-capable weights above for binder evaluation. Do not rely on an unspecified model or weight default.

3. Score

Upload complete design/ and holo predictions/ outputs together to Score Refolded Designs, retaining manifests and .cbor.gz detailed scores. Use this folder layout:

input/
├── design/             # complete design task output
├── predictions/        # complete holo prediction output
└── apo-predictions/    # optional complete apo prediction output

Set cofoldingModel to the matching label above and criterion: "auto". This records which model ran. Model selection happens in Predict Structure. Find the CSV through score/result.json. To compare predictors, repeat prediction and scoring separately on the same designs. Keep each model's scores separate.

Monomer Backbone RMSD ≤ 1.5 Å
Protein binder Binder pTM ≥ 0.8. Interface PAE ≤ 1.5 Å. Target-backbone-aligned binder RMSD ≤ 2.5 Å
Antibody Interface PAE ≤ 2.0 Å. Target-aligned binder RMSD ≤ 2.0 Å

Read pass, status and pass_note. Empty pass means missing evidence. Preliminary filter failures cannot pass. Pose scoring needs group-0 target atoms, and Fv interface metrics include VH–VL contacts. Compare results within one predictor/protocol. Thresholds were calibrated with upstream's AF3 oracle. If refold/error.json reports a template mismatch, split the designs into compatible target/framework groups. Keep detailed scores enabled for binder metrics. An optional passCriteria file changes thresholds. Leave it unset for the vendored criteria.

About RFD4-Proteina

RFD4-Proteina is a generative protein design model from NVIDIA and the Baker Lab. It designs a protein's sequence and its full-atom 3D structure together, conditioned on a target you give it. Apheris Foundry runs it as three workflows:

Workflow ID What it does
Design Proteins rfd4-proteina-design Generates designs, and optionally prepares the best ones for refolding
Score Refolded Designs rfd4-proteina-refold-score Scores folding-model refolds of designs against RFD4-Proteina's pass criteria
Fine-Tune Protein Design Model rfd4-proteina-finetune Trains the design model further on your own structures

What it designs

  • Antibodies: VHHs (nanobodies) and paired VH/VL (Fv). It designs new CDRs against an epitope you choose, or redesigns selected CDRs of an existing antibody. See How to design an antibody.
  • Miniprotein binders to protein targets.
  • Binders to small molecules, DNA and RNA.
  • Enzymes built around a catalytic motif, and scaffolds for a given functional motif.
  • Monomers from scratch.

It can also refine an earlier design (partial diffusion) or design new sequences for a kept backbone (inverse folding).

Models available for RFD4-Proteina

RFD4-Proteina uses two kinds of model: a design model that generates proteins, and a folding model that refolds each design to check it.

How to design an antibody with RFD4-Proteina

Use the antibody model, weight antibody-2026-10-30, in Design Proteins. It designs new CDR loops against an epitope you choose and keeps the antibody framework fixed. It handles VHHs (nanobodies) and paired VH/VL (Fv). For a Fab or IgG, design the Fv and add the constant domains afterwards.

What to prepare

  1. The antigen as an mmCIF file. PDB files are rejected.
  2. A framework: a VHH or VH/VL structure whose framework you want to keep, such as a clinical antibody.
  3. The epitope: a few antigen atoms the antibody should contact (hotspots).
  4. A length range for each CDR.

The design spec

A short JSON or YAML file says what to keep and what to design. From the Fv example (full file), which designs six CDRs on adalimumab's framework against ubiquitin (chain F):

{
  "contig": "F1-76, /0, H1-22, 13-15, H24-37, 9-10, H39-75, 11-22, H77-87, /0, L1-23, 11-14, L25-38, 8-8, L40-71, 8-12, L73-82",
  "conditions": {
    "C_CRD":    {"true": [{"select": "sel('F/*/*/[N,CA,C,O]')"}]},
    "C_CRDGRP": {"1": [{"select": "sel('H/*/[1-22, 24-37, 39-75, 77-87]/[N,CA,C,O]')"},
                       {"select": "sel('L/*/[1-23, 25-38, 40-71, 73-82]/[N,CA,C,O]')"}]},
    "C_SEQ":    {"true": [{"select": "sel('F')"}, {"select": "sel('H/*/[1-22, 24-37, 39-75, 77-87]')"},
                          {"select": "sel('L/*/[1-23, 25-38, 40-71, 73-82]')"}]},
    "C_HOT":    {"true": [{"select": "sel('F/*/8/CD1')"}, {"select": "sel('F/*/70/CG1')"}]},
    "C_CATH":   {"2.60.40": [{"select": "sel('H')"}, {"select": "sel('L')"}]}
  }
}
  • contig lays out the chains. Ranges with a chain letter are kept from the input. Bare ranges such as 13-15 are designed CDRs of that length. /0 starts a new chain.
  • C_SEQ keeps the sequence of the antigen and the framework.
  • C_CRD keeps the antigen backbone where it is.
  • C_CRDGRP keeps the framework's internal shape. Put VH and VL in one group so they stay paired.
  • C_HOT marks the epitope atoms.
  • C_CATH marks the antibody chains as an immunoglobulin fold (2.60.40).

Residue numbers are the file's own (label_seq_id). A VHH spec has one antibody chain and three CDRs.

To redesign selected CDRs of an existing antibody instead, keep every other CDR in C_SEQ and C_CRDGRP and leave only the ones to redesign as bare ranges. For trastuzumab's CDRH3 against HER2, the HER2 models give better starting points than the general antibody model.

Run it

apheris-foundry workflows run --workflow rfd4-proteina-design \
  --input Data/03-fv --weight antibody-2026-10-30 \
  --param numReplicates=100 --param batchSize=1 --param seed=1 \
  --param recycleStrategy=high/front_loaded \
  --param refold=true --param refoldTopN=20 --wait

Use recycleStrategy=high/front_loaded for antibodies. Plan 100 to 200 designs per target: upstream reports binder pass rates around 8 to 11%. On an A100 a VHH takes about 24 s per design and a VH/VL about 36 s.

Check the designs

Refold the prepared designs with a folding model and score them: see Refolding. Look at the antigen contacts in each accepted complex. For an Fv, scoring picks one chain of interest and counts the other antibody domain as a partner, so a good interface score can reflect VH-VL confidence rather than antigen binding.

To explore close variants of a promising design, run Design Proteins on its *_generated.cif with partialTrajectoryFraction set (see Refine a binder).

Check designs by refolding them

A design is worth testing when an independent folding model, given only its sequence, folds it into the designed complex. Foundry runs this in three steps:

  1. Design Proteins with refold=true prepares the best designs for refolding (the top 20% by default, or refoldTopN).
  2. Predict Structure refolds them with a folding model, once bound to the target (holo) and once alone (apo).
  3. Score Refolded Designs scores each refold against RFD4-Proteina's pass criteria, taken from the upstream AlphaFold3 check: confidence in the binder, confidence in the interface, and agreement with the designed structure.

The folding models and their score labels are listed in Models. For binders, prefer one that uses a template. The cut-offs were calibrated on AlphaFold3 and can shift by model, so compare pass rates within one model.

Upstream reports binder pass rates of 7.7% to 10.6%, so plan 100 to 200 designs per target. On an A100, refolding takes about 25 s per design per model, plus 20 s for the apo run.

The full protocol and the exact pass criteria are in Evaluate candidates. Upstream's own metrics, without refolding, are in Advanced routes.

Trastuzumab and HER2

Trastuzumab is a clinical antibody that binds HER2, a receptor on some breast cancer cells. Both tables come from Chinery et al., who changed trastuzumab's CDRH3 (the third loop of the heavy chain, its main contact with HER2) and measured how the variants bind. The hackathon organisers at the University of Oslo prepared them as tables. Cite Chinery et al. when you use them.

These two tables are the "provided data" for the challenge filter: a design must differ from every CDRH3 in both of them (525,063 unique sequences). See HER2 models.

FACS binding classes

tz_her2_facs_3classes_524346.csv.zip holds 524,346 trastuzumab variants, each with a different 10-residue CDRH3. Each variant was shown on the surface of a cell and sorted by how strongly it bound HER2 (FACS, fluorescence-activated cell sorting). Use it to train a binder or non-binder classifier, or to check a design for novelty.

Column Meaning
cdrh3 The CDRH3 sequence, always 10 residues
binding_class high (172,149), medium (190,011) or low (162,186) HER2 binding
vh_sequence The full heavy-chain variable domain (VH) carrying this CDRH3
vl_sequence Trastuzumab's light-chain variable domain (VL), the same in every row
edit_distance How many CDRH3 positions differ from trastuzumab's (WGGDGFYAMD), 1 to 10

The classes say whether a variant binds, not how tightly. Trastuzumab itself is not in the table.

SPR affinities

trastuzumab_her2_spr_all_768.csv holds 768 designed variants whose binding to HER2 was measured by surface plasmon resonance (SPR), which reports affinity as a dissociation constant (KD). A lower KD means tighter binding. 190 rows have a KD. Use it to train or test an affinity predictor, or to rank binders.

Column Meaning
cdrh3 The CDRH3 sequence, 9 or 10 residues for trastuzumab variants
vh_sequence, vl_sequence The full variable domains that were measured
kd_nM KD in nanomolar, filled only for quantified_binding (0.023 to 13,863 nM, median 64 nM)
binding_result quantified_binding (190), no_reportable_kd (460, measured with no KD reported), inconclusive (104) or not_reported (14)

Trastuzumab itself appears 8 times as a reference, with KD 0.03 to 0.18 nM. Another 8 rows are a different antibody (CDRH3 ARDRIVDDYYYYGMDV, different VH and VL) with no KD. Drop them when you model trastuzumab variants. 37 SPR CDRH3s also appear in the FACS table.

Antibody-antigen structure predictions

Smorodina et al. (CC BY 4.0) folded 106 known nanobody-antigen pairs and 11,342 shuffled pairs, in which each nanobody is matched with an antigen it does not bind, with AlphaFold3, Boltz-2 and Chai-1. Their finding: a folding model's interface confidence (ipTM) often fails to tell a real pair from a shuffled one. Use these tables to check how far to trust a folding model's confidence when you rank designs.

Technical reference: what to pass

Design instructions: the uploaded spec

Each top-level design ID maps to input, optional contig, conditions and input_as_annotated_cif. Relative structure paths resolve from the spec's directory and must stay inside the uploaded tree. Upload every referenced file. With multiple specs, set workflow spec to the chosen relative filename. The optional top-level global_args supplies defaults shared by the design IDs.

Field / condition Meaning
input One CIF/BCIF path or a list of structures with distinct chain IDs
input_as_annotated_cif: true Preserve existing conditioning. Default is false for freshly prepared inputs
contig Retained residue ranges, expandable lengths and /0 chain breaks
C_SEQ Preserve selected residue identities
C_CRD Fix selected atoms in absolute coordinates. Group 0 supplies the pose-scoring frame
C_CRDGRP: 1 Preserve internal geometry while allowing rigid-body placement. Use for framework backbones
C_HOT Request contacts to selected target atoms
C_CATH: "2.60.40" Supply immunoglobulin fold context on antibody chains
C_RAS Exposure bin: BURIED, INTERMEDIATE, EXPOSED or UNSPECIFIED
C_HB Hydrogen-bond role: DONOR, ACCEPTOR or BOTH
C_PISTACK, C_PICATION Stacking: true. Aromatic/cation role: AROMATIC, CATION or BOTH
C_CENTROID Literal "x,y,z" chain centroid, covering every atom of every chain
C_IDX: false Unindex selected atoms, with a shared group label where their relative offsets must remain linked

CDR lengths and hotspot selections are input conditions, not workflow flags. An ordinary CIF needs an explicit design problem. Side-chain coordinate conditioning also reveals residue identity. Backbone-only conditions permit sequence redesign where sequence is not fixed. For complete selection syntax and condition values, see the optional online spec reference.

Design Proteins: workflow parameters

Parameter Meaning and default
input, output Upload directory and persistent result root. Keep output/work directories outside input
spec Relative JSON/YAML spec filename. Inferred for a sole top-level spec
numReplicates Designs per input, 1–200. Default 1
batchSize Generation batch size. Default 1
seed Nonnegative integer. Random when omitted

resampleHotspots Default false. true replaces annotated hotspots with 2–3 sampled nearby atoms
partialTrajectoryFraction Omit for fresh generation. Fraction in (0,1] covering at least one of 60 steps, on an annotated generated parent

Advanced routes

The supplied Hub workflows cover design, prediction and refold scoring. The module also exposes finetune and metrics tasks. Run these through a workflow that exposes them, or inside the supplied module container. Their snake_case configuration keys are not Design Proteins workflow parameters.

Fine-tune the generator

Provide a Parquet dataset with example_id, path and the metadata required by the upstream PLINDER training recipe. Every referenced CIF must exist under the structures root. Use compatible base weights and the paired autoencoder.

Inside the configured module container, with the dataset mounted at /data:

module-run finetune --input /data/train.parquet --output /output/train \
  --config '{"structures":"/data/cifs","epochs":1,"steps_per_epoch":50,"batch_size":1,"learning_rate":0.00001,"seed":42,"task_mix":"antibody"}'

Choose task_mix: "plinder" for the general training mix. Antibody training requires a protein antigen and _atom_site.ig_region labels on antibody atoms (framework, cdr1–cdr4). The autoencoder stays frozen. Training saves regular and EMA checkpoints under training/checkpoints/ and lists them in result.json. Use a compatible *-ema.ckpt for inference and retain its paired autoencoder. Assess it on independent data before scaling up.

Recalculate metrics or cluster designs

Use a directory containing only the intended designs, excluding references and refold outputs:

module-run metrics --input /data/designs --output /output/metrics \
  --config '{"metrics_tags":["design","hotspot_conditioning"],"cluster":false}'

Optional task_csv assigns structures to task groups. cluster: true requires Foldseek through FOLDSEEK_EXEC. Read per-design, per-task and aggregate CSVs from result.json, and compare report rows with the input count. Oracle tags such as antibody and *_refolding are rejected by this image. Use Predict Structure and Score Refolded Designs for refolding.

Fixed-backbone redesign and upstream options

inverseFolding is exposed by the inspected workflow and pinned contract, but the local module's DesignConfig lacks it. Confirm the deployed pair supports it. It needs coordinates for every designed residue and cannot be combined with expandable segments, partial diffusion or hotspot resampling.

Reward-guided search and metric guidance use upstream configuration beyond the supplied workflow controls. Folding an existing sequence uses Predict Structure directly. Context-conditioned design is covered in other tasks.

Symptom What to check
Missing input or settings Use the embedded downloads in the Files tab. Extract the input ZIP and retain the displayed folder names. Settings are separate from the upload.
Workflow or antibody weight absent Run workflows list and workflows models for the selected workflow. Ask your platform team for the required access or deployment.
Field rejected Read workflows docs for that workflow. Design settings use camelCase, prediction settings belong inside modelParams, and module tasks use snake_case.
GPU out of memory Start with batchSize: 1 and one antibody candidate. If it still fails, use a smaller design problem or a GPU with sufficient memory.
Designs exist but refold preparation failed Keep design/ and inspect refold/error.json. A shared template requires compatible target/framework geometry and lengths. Prepare compatible groups separately.
Missing binder metrics Retain the complete prediction output, including .cbor.gz scores. Set write_detailed_scores: true and check prediction failures.
